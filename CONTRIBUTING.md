# Contributing to wiremock-ts

Thanks for your interest. This document is the source of truth for how the project is built; changes that follow it review quickly.

## Getting started

- Node 20+ (developed on Node 24) and npm.
- `npm install` — note this regenerates the lockfile fully (see [Dependencies](#dependencies)).
- `npm run dev` runs the CLI under `tsx watch`.

## The gate

Every change must pass these locally before you push, and CI runs them on Node 20, 22 and 24:

```bash
npm run typecheck     # tsc --noEmit
npm run lint          # eslint, flat config
npm run format:check  # prettier
npm test              # vitest
npm run build         # tsup (esm + .d.ts)
```

Don't push red.

## Code style

- **TypeScript, ESM, no `.js` import extensions.** The project uses `moduleResolution: bundler`; import `./foo`, never `./foo.js`.
- **Named exports only** — no default exports (the only exceptions are tool config files that require one, e.g. `eslint.config.mjs`, `vitest.config.ts`).
- **Formatting is Prettier** (4-space indent, 100 columns). Run `npm run format` — it organises imports first (`organize-imports-cli` strips unused imports, then `@ianvs/prettier-plugin-sort-imports` groups them: node built-ins → external → relative, separated by blank lines) and then formats.
- **Comments** are lowercase, British spelling, and used only where they earn their place. No banners or ASCII art.
- **No emojis** in source.
- **Strict types.** `noUncheckedIndexedAccess` and `verbatimModuleSyntax` are on — use `import type` for type-only imports. Avoid `any`; prefer `unknown` and narrow.

## Dependencies

- **Pin exact versions — never `^` or `~`.** Check the current version on npm before adding anything, and prefer the standard library or a small dependency over a heavy one.
- After changing dependencies, **regenerate the lockfile with a full `npm install`** — do not use `npm install --package-lock-only`, which omits optional package nodes and makes `npm ci` fail.

## Tests

Vitest, under `test/`. Unit-test pure logic directly; for anything involving the server, start one on `port: 0` (an ephemeral port) and drive it over `fetch`. New behaviour ships with tests; `npm run test:coverage` reports coverage.

## Commits and pull requests

- Small, focused commits. Messages use `type(scope): summary` in the imperative, lowercase (e.g. `feat(dsl): add anyUrl matcher`).
- Branch off `develop` and open pull requests against `develop`.
- Do not add co-authors, "generated by" trailers, or any tool attribution to commits or PR descriptions.

## Releasing

Bump the `version` in `package.json` and push a matching `vX.Y.Z` tag; the release workflow builds and publishes to npm.
